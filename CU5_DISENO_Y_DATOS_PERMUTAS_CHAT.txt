1. DISENO LOGICO (MODELO CONCEPTUAL / RELACIONAL)
--------------------------------------------------------------------------------
El modulo de Permutas de Horario y Mensajeria Interna (CU5) administra la asignacion
recurrente de turnos de atencion a los auxiliares de laboratorio, el flujo formal de
intercambio temporal de turnos en 3 fases (solicitud -> aceptacion -> aprobacion) y
la comunicacion interna mediante mensajes entre auxiliares y con el Encargado.

A. ENTIDADES Y DEFINICION LOGICA:
  * TURNO (id, semestre_id, auxiliar_id, laboratorio_id, dia_semana, hora_inicio, hora_fin)
    Horario semanal obligatorio de atencion asignado a un auxiliar en un laboratorio.

  * PERMUTA (id, turno_id, solicitante_id, reemplazante_id, fecha, estado, aprobado_por, creado_en)
    Acuerdo temporal y puntual para que un auxiliar cubra el turno de otro en una fecha dada.

  * MENSAJE (id, remitente_id, destinatario_id, contenido, leido, enviado_en)
    Mensajeria interna privada para coordinar relevos, permutas o consultas administrativas.

B. RELACIONES Y CARDINALIDADES:
  * SEMESTRE (1) ──── (N) TURNO
    Cada turno pertenece a un periodo semestral especifico ('semestre_id').
  * USUARIO [AUXILIAR] (1) ──── (N) TURNO
    Un auxiliar tiene uno o varios turnos asignados a la semana ('auxiliar_id').
  * LABORATORIO (1) ──── (N) TURNO (Opcional / Nulo si atiende modulo general)
    El turno se cumple en un laboratorio especifico ('laboratorio_id').
  * TURNO (1) ──── (N) PERMUTA
    Un turno base puede ser permutado en diferentes fechas ('turno_id').
  * USUARIO (1) ──── (N) PERMUTA (como solicitante y como reemplazante)
    Participan el titular que cede el turno ('solicitante_id') y quien lo cubre ('reemplazante_id').
  * USUARIO [ENCARGADO] (1) ──── (N) PERMUTA (Opcional mientras este PENDIENTE o ACEPTADA)
    El Encargado autoriza o rechaza formalmente el relevo ('aprobado_por').
  * USUARIO (1) ──── (N) MENSAJE (como remitente y como destinatario)
    Relacion reflexiva de comunicacion entre usuarios autorizados ('remitente_id', 'destinatario_id').

C. REGLAS DE NEGOCIO E INTEGRIDAD:
  1. Flujo Estricto de 3 Fases: SOLPMT (solicitud por el titular) -> ACEPMT / RECPMT (aceptacion
     o rechazo por el reemplazante) -> APRPMT / RECPMT (aprobacion o rechazo final por el Encargado).
  2. Temporalidad y Fecha Unica: La permuta aplica exclusivamente para la fecha especificada.
     No modifica la asignacion permanente del turno base en la tabla 'turno'.
  3. Distincion Obligatoria de Actores: El solicitante no puede ser igual al reemplazante ('CHECK solicitante <> reemplazante').
  4. No Choque de Turnos: El reemplazante no puede tener otro turno asignado en el mismo dia y franja horaria.
  5. Impacto en Asistencia: Cuando una permuta esta 'APROBADA', la obligacion de marcar asistencia
     (CU7) para ese turno y fecha se transfiere formalmente al reemplazante.
  6. Estados Permitidos: 'PENDIENTE', 'ACEPTADA', 'APROBADA', 'RECHAZADA'.

4. SCRIPT SQL COMPLETO (DDL Y DML)
--------------------------------------------------------------------------------
-- SCRIPT DDL: CREACION DE TABLAS (CU5)
CREATE TABLE turno (
  id             SERIAL PRIMARY KEY,
  semestre_id    INT NOT NULL REFERENCES semestre(id),
  auxiliar_id    INT NOT NULL REFERENCES usuario(id),
  laboratorio_id INT REFERENCES laboratorio(id),
  dia_semana     SMALLINT NOT NULL CHECK (dia_semana BETWEEN 1 AND 6),
  hora_inicio    TIME NOT NULL,
  hora_fin       TIME NOT NULL,
  CHECK (hora_fin > hora_inicio)
);

CREATE TABLE permuta (
  id              SERIAL PRIMARY KEY,
  turno_id        INT  NOT NULL REFERENCES turno(id),
  solicitante_id  INT  NOT NULL REFERENCES usuario(id),
  reemplazante_id INT  NOT NULL REFERENCES usuario(id),
  fecha           DATE NOT NULL,
  estado          VARCHAR(10) NOT NULL DEFAULT 'PENDIENTE'
                  CHECK (estado IN ('PENDIENTE','ACEPTADA','APROBADA','RECHAZADA')),
  aprobado_por    INT REFERENCES usuario(id),
  creado_en       TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
  CHECK (solicitante_id <> reemplazante_id)
);

CREATE TABLE mensaje (
  id              SERIAL PRIMARY KEY,
  remitente_id    INT  NOT NULL REFERENCES usuario(id),
  destinatario_id INT  NOT NULL REFERENCES usuario(id),
  contenido       TEXT NOT NULL,
  leido           BOOLEAN NOT NULL DEFAULT FALSE,
  enviado_en      TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);
