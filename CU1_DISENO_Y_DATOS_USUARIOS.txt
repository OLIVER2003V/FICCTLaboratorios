1. DISENO LOGICO (MODELO CONCEPTUAL / RELACIONAL)
--------------------------------------------------------------------------------
El modulo de Seguridad y Gestion de Usuarios (CU1) administra las identidades,
cuentas de correo electronico autorizadas y privilegios de acceso al sistema.

A. ENTIDADES Y DEFINICION LOGICA:
  * ROL (id, codigo, nombre, descripcion)
    Define los perfiles del sistema: Encargado (ENC), Director (DIR),
    Docente (DOC) y Auxiliar (AUX).

  * USUARIO (id, codigo, nombre, apellido, correo, telefono, cargo, aula, gestion, rol_id, estado, creado_en)
    Almacena las personas autorizadas que interactuan via correo electronico.

  * COMANDO (id, nombre, descripcion)
    Catalogo de comandos interpretables por el procesador de correos.

  * ROL_COMANDO (rol_id, comando_id)
    Matriz de permisos (M:N) que asocia que comandos puede ejecutar cada rol.

B. RELACIONES Y CARDINALIDADES:
  * ROL (1) ------ (N) USUARIO
    Un rol puede estar asignado a uno o muchos usuarios. Todo usuario tiene asignado
    exactamente un rol obligatorio mediante la clave foranea 'rol_id'.
  * ROL (N) ------ (M) COMANDO
    Relacion de muchos a muchos implementada a traves de la tabla puente ROL_COMANDO.

C. REGLAS DE NEGOCIO E INTEGRIDAD:
  1. Unicidad de Correo: El correo electronico debe ser unico y valido (Gmail).
  2. Unicidad de Codigo: Cada usuario posee un codigo unico (Registro Universitario o COD_EMP).
  3. Dominio de Roles: Exclusivamente 'ENC', 'DIR', 'DOC' o 'AUX'.
  4. Estado y Baja Logica: El estado solo admite 'ACTIVO' o 'INACTIVO'. No se borran
     usuarios fisicamente para mantener la integridad referencial historica.
  5. Atributos de Auxiliares: Para rol 'AUX', opcionalmente se almacena el aula asignada
     (ej. '236-41') y la gestion academica activa (ej. '2-2026').

+-------------+--------------+----------+---------------------------------------------------+

-- SCRIPT DDL: CREACION DE TABLAS (CU1)
CREATE TABLE rol (
  id          SERIAL PRIMARY KEY,
  codigo      VARCHAR(3)  NOT NULL UNIQUE,
  nombre      VARCHAR(50) NOT NULL,
  descripcion VARCHAR(200)
);

CREATE TABLE comando (
  id          SERIAL PRIMARY KEY,
  nombre      VARCHAR(10)  NOT NULL UNIQUE,
  descripcion VARCHAR(200) NOT NULL
);

CREATE TABLE rol_comando (
  rol_id     INT NOT NULL REFERENCES rol(id),
  comando_id INT NOT NULL REFERENCES comando(id),
  PRIMARY KEY (rol_id, comando_id)
);

CREATE TABLE usuario (
  id        SERIAL PRIMARY KEY,
  codigo    VARCHAR(20)  NOT NULL UNIQUE,
  nombre    VARCHAR(60)  NOT NULL,
  apellido  VARCHAR(60)  NOT NULL,
  correo    VARCHAR(100) NOT NULL UNIQUE,
  telefono  VARCHAR(20),
  cargo     VARCHAR(60),
  aula      VARCHAR(20),
  gestion   VARCHAR(10),
  rol_id    INT NOT NULL REFERENCES rol(id),
  estado    VARCHAR(10) NOT NULL DEFAULT 'ACTIVO'
            CHECK (estado IN ('ACTIVO','INACTIVO')),
  creado_en TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);
