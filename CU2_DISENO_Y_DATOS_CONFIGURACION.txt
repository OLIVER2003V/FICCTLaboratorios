1. DISENO LOGICO (MODELO CONCEPTUAL / RELACIONAL)
--------------------------------------------------------------------------------
El modulo de Configuracion Semestral y Perfiles (CU2) administra la infraestructura
fisica (laboratorios), la planificacion del calendario academico (semestres, feriados,
mantenimientos y suspensiones de actividades) y la matriz de perfiles y permisos.

A. ENTIDADES Y DEFINICION LOGICA:
  * LABORATORIO (id, codigo, nombre, capacidad, ubicacion, estado)
    Modulos y salas de computo o auditorios disponibles en la facultad.

  * SEMESTRE (id, gestion, fecha_inicio, fecha_fin, estado)
    Periodos academicos semestrales (ej. '2-2026', '1-2027'). Controla el ciclo
    de vida: PLANIFICADO -> ACTIVO -> CERRADO.

  * FECHA_BLOQUEADA (id, semestre_id, fecha, tipo, motivo, laboratorio_id)
    Dias no habiles o de restriccion total/parcial (feriados nacionales, departamentales,
    mantenimiento preventivo, jornadas PSA, fumigacion).

  * ROL_COMANDO (rol_id, comando_id)
    Matriz de perfiles de acceso que define que comandos estan habilitados para cada rol
    (gestionado dinamicamente con el comando ASICOM).

B. RELACIONES Y CARDINALIDADES:
  * SEMESTRE (1) ──── (N) FECHA_BLOQUEADA
    Un semestre agrupa una o muchas fechas bloqueadas. Toda fecha bloqueada pertenece
    obligatoriamente a un semestre mediante la clave foranea 'semestre_id'.
  * LABORATORIO (1) ──── (N) FECHA_BLOQUEADA (Opcional / Nulo)
    Un bloqueo puede afectar especificamente a un solo laboratorio ('laboratorio_id')
    o si 'laboratorio_id' es NULL, el bloqueo tiene alcance global (Todos los laboratorios).
  * ROL (N) ──── (M) COMANDO (via ROL_COMANDO)
    Permite asignar o revocar comandos a roles para configurar privilegios.

C. REGLAS DE NEGOCIO E INTEGRIDAD:
  1. Restriccion de Semestre Activo: Solo puede existir UN (1) semestre en estado 'ACTIVO'
     al mismo tiempo (garantizado por el indice unico condicional ux_semestre_activo).
  2. Secuencia Temporal: La fecha de finalizacion ('fecha_fin') de un semestre debe ser
     estrictamente posterior a su fecha de inicio ('fecha_inicio').
  3. Ciclo de Vida Semestral: Un semestre nace como 'PLANIFICADO', pasa a 'ACTIVO' (cerrando
     el semestre previo) y concluye como 'CERRADO'.
  4. Capacidad de Laboratorio: La capacidad debe ser estrictamente mayor a 0.
  5. Estados de Laboratorio: Exclusivamente 'DISPONIBLE', 'MANTENIMIENTO' o 'INHABILITADO'.
  6. Tipos de Fechas Bloqueadas: 'FERIADO', 'PSA', 'MANTENIMIENTO' u 'OTRO'.
  7. Bloqueo Preventivo: Las fechas bloqueadas impiden de forma estricta cualquier reserva
     o clase en los laboratorios afectados durante ese dia.

4. SCRIPT SQL COMPLETO (DDL Y DML)
--------------------------------------------------------------------------------
-- SCRIPT DDL: CREACION DE TABLAS (CU2)
CREATE TABLE laboratorio (
  id        SERIAL PRIMARY KEY,
  codigo    VARCHAR(10) NOT NULL UNIQUE,
  nombre    VARCHAR(60) NOT NULL,
  capacidad INT NOT NULL CHECK (capacidad > 0),
  ubicacion VARCHAR(100),
  estado    VARCHAR(15) NOT NULL DEFAULT 'DISPONIBLE'
            CHECK (estado IN ('DISPONIBLE','MANTENIMIENTO','INHABILITADO'))
);

CREATE TABLE semestre (
  id           SERIAL PRIMARY KEY,
  gestion      VARCHAR(10) NOT NULL UNIQUE,
  fecha_inicio DATE NOT NULL,
  fecha_fin    DATE NOT NULL,
  estado       VARCHAR(12) NOT NULL DEFAULT 'PLANIFICADO'
               CHECK (estado IN ('PLANIFICADO','ACTIVO','CERRADO')),
  CHECK (fecha_fin > fecha_inicio)
);
CREATE UNIQUE INDEX ux_semestre_activo ON semestre (estado) WHERE estado = 'ACTIVO';

CREATE TABLE fecha_bloqueada (
  id             SERIAL PRIMARY KEY,
  semestre_id    INT  NOT NULL REFERENCES semestre(id),
  fecha          DATE NOT NULL,
  tipo           VARCHAR(15) NOT NULL
                 CHECK (tipo IN ('FERIADO','PSA','MANTENIMIENTO','OTRO')),
  motivo         VARCHAR(200),
  laboratorio_id INT REFERENCES laboratorio(id)  -- NULL: afecta a todos
);
