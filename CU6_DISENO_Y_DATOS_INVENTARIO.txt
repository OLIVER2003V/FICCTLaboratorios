--------------------------------------------------------------------------------
1. DISENO LOGICO (MODELO CONCEPTUAL / RELACIONAL)
--------------------------------------------------------------------------------
El modulo de Inventario, Incidencias, Objetos Encontrados y Red (CU6) administra
el control fisico y logico de todos los activos tecnologicos (computadoras, proyectores,
perifericos, componentes) en los 9 laboratorios de la facultad, la asignacion de parametros
de red estatica por estacion de trabajo, el ciclo de vida de incidencias tecnicas y la
custodia formal de objetos extraviados y devueltos a la comunidad universitaria.

A. ENTIDADES Y DEFINICION LOGICA:
  * EQUIPO (id, activo, codigo, laboratorio_id, tipo, descripcion, estado)
    Representa el activo fisico o logico inventariado en un laboratorio determinado.
    Valores de tipo: COMPUTADORA, PROYECTOR, COMPONENTE, SOFTWARE, OTRO.
    Valores de estado: OPERATIVO, EN_REPARACION, BAJA.

  * EQUIPO_RED (id, equipo_id, ip, mascara, gateway, dns1, dns2, proxy, grupo_red)
    Configuracion de red local TCP/IP asignada a una estacion de trabajo o equipo activo.
    Mantiene relacion 1 a 1 exclusiva con el equipo correspondiente.

  * INCIDENCIA (id, equipo_id, reportado_por, descripcion, estado, solucion, fecha_reporte, fecha_solucion)
    Falla de hardware, software o conectividad reportada sobre un equipo especifico.
    Valores de estado: PENDIENTE, EN_ATENCION, RESUELTA.

  * OBJETO_ENCONTRADO (id, laboratorio_id, descripcion, fecha_hallazgo, registrado_por, estado, entregado_a, ci_receptor, fecha_entrega)
    Pertenencia u objeto personal extraviado en laboratorios y dejado bajo custodia del auxiliar.
    Valores de estado: EN_CUSTODIA, ENTREGADO.

B. RELACIONES Y CARDINALIDADES:
  * LABORATORIO (1) ──── (N) EQUIPO
    Cada equipo esta fisicamente ubicado y catalogado en un laboratorio ('laboratorio_id').
  * EQUIPO (1) ──── (0..1) EQUIPO_RED
    Relacion 1 a 1: Cada registro de red pertenece de forma unica a un equipo ('equipo_id').
    Si el equipo es eliminado, su configuracion de red se borra en cascada (ON DELETE CASCADE).
  * EQUIPO (1) ──── (N) INCIDENCIA
    Un equipo puede tener un historial cronologico de fallas tecnicas registradas ('equipo_id').
  * USUARIO (1) ──── (N) INCIDENCIA
    El usuario (docente, auxiliar o encargado) que realiza el reporte de la falla ('reportado_por').
  * LABORATORIO (1) ──── (N) OBJETO_ENCONTRADO
    El laboratorio fisico donde se encontro el objeto extraviado ('laboratorio_id').
  * USUARIO [AUXILIAR / ENCARGADO] (1) ──── (N) OBJETO_ENCONTRADO
    El auxiliar de turno que recibe y registra la custodia inicial ('registrado_por').

C. REGLAS DE NEGOCIO E INTEGRIDAD:
  1. Unicidad de Codigo y Activo Fijo: El codigo interno del equipo debe ser unico en el sistema (UNIQUE).
  2. Segmentacion de Red: La IP asignada a cada equipo debe ser unica dentro de la red facultativa.
  3. Flujo de Incidencias: PENDIENTE -> EN_ATENCION -> RESUELTA. Al resolverse la incidencia, es obligatorio
     ingresar el detalle de la solucion tecnica aplicada y se sella automaticamente la fecha de solucion.
  4. Cadena de Custodia: El objeto encontrado permanece en estado 'EN_CUSTODIA' hasta que el propietario
     acredita pertenencia. Al devolverse, pasa a 'ENTREGADO' registrando obligatoriamente nombre,
     CI del receptor y la fecha/hora exacta de la entrega.
  5. Notificacion Automatica: Cuando se reporta una incidencia de estado PENDIENTE, el sistema notifica
     inmediatamente al Encargado del Laboratorio para su asignacion y atencion tecnica.

-- SCRIPT DDL: CREACION DE TABLAS (CU6)
CREATE TABLE equipo (
  id             SERIAL PRIMARY KEY,
  activo         VARCHAR(30),
  codigo         VARCHAR(50) NOT NULL UNIQUE,
  laboratorio_id INT NOT NULL REFERENCES laboratorio(id),
  tipo           VARCHAR(50) NOT NULL,
  descripcion    VARCHAR(200) NOT NULL,
  estado         VARCHAR(15) NOT NULL DEFAULT 'OPERATIVO'
                 CHECK (estado IN ('OPERATIVO','EN_REPARACION','BAJA'))
);

CREATE TABLE equipo_red (
  id          SERIAL PRIMARY KEY,
  equipo_id   INT NOT NULL UNIQUE REFERENCES equipo(id) ON DELETE CASCADE,
  ip          VARCHAR(45) NOT NULL,
  mascara     VARCHAR(15) NOT NULL DEFAULT '255.255.255.0',
  gateway     VARCHAR(45) NOT NULL DEFAULT '172.20.172.254',
  dns1        VARCHAR(45) NOT NULL DEFAULT '10.10.0.251',
  dns2        VARCHAR(45) NOT NULL DEFAULT '8.8.8.8',
  proxy       VARCHAR(45) NOT NULL DEFAULT '172.20.172.254:3128',
  grupo_red   VARCHAR(20) NOT NULL DEFAULT 'LAB41'
);

CREATE TABLE incidencia (
  id             SERIAL PRIMARY KEY,
  equipo_id      INT NOT NULL REFERENCES equipo(id),
  reportado_por  INT NOT NULL REFERENCES usuario(id),
  descripcion    VARCHAR(300) NOT NULL,
  estado         VARCHAR(12) NOT NULL DEFAULT 'PENDIENTE'
                 CHECK (estado IN ('PENDIENTE','EN_ATENCION','RESUELTA')),
  solucion       VARCHAR(300),
  fecha_reporte  TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
  fecha_solucion TIMESTAMP
);

CREATE TABLE objeto_encontrado (
  id             SERIAL PRIMARY KEY,
  laboratorio_id INT  NOT NULL REFERENCES laboratorio(id),
  descripcion    VARCHAR(200) NOT NULL,
  fecha_hallazgo DATE NOT NULL,
  registrado_por INT  NOT NULL REFERENCES usuario(id),
  estado         VARCHAR(12) NOT NULL DEFAULT 'EN_CUSTODIA'
                 CHECK (estado IN ('EN_CUSTODIA','ENTREGADO')),
  entregado_a    VARCHAR(100),
  ci_receptor    VARCHAR(15),
  fecha_entrega  TIMESTAMP
);
